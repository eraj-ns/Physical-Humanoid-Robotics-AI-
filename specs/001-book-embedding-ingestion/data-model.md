# Data Model: Book Embedding Ingestion Pipeline

## Documentation Chunk
**Description**: Represents a segment of text extracted from documentation with associated metadata for retrieval.

**Fields**:
- `id` (string): Unique identifier for the chunk
- `content` (string): The actual text content extracted from documentation
- `source_url` (string): URL of the original documentation page
- `title` (string): Title of the documentation page
- `created_at` (datetime): Timestamp when the chunk was created
- `updated_at` (datetime): Timestamp when the chunk was last updated
- `metadata` (dict): Additional metadata about the chunk (section, tags, etc.)

## Embedding Vector
**Description**: Numerical representation of text content generated by Cohere models, stored in Qdrant for similarity search.

**Fields**:
- `id` (string): Unique identifier matching the documentation chunk
- `vector` (list[float]): The embedding vector (typically 1024-dimensional for Cohere)
- `chunk_id` (string): Reference to the corresponding documentation chunk
- `model_version` (string): Version of the embedding model used

## Source Metadata
**Description**: Information about the original documentation page including URL, title, and any relevant contextual data.

**Fields**:
- `source_url` (string): The original URL of the documentation page
- `title` (string): Title of the documentation page
- `last_crawled` (datetime): Timestamp of the last crawl
- `status` (string): Status of the crawl (success, failed, etc.)
- `checksum` (string): Content checksum to detect changes

## Configuration Object
**Description**: Contains API keys, URLs, and parameters needed for the ingestion pipeline components.

**Fields**:
- `cohere_api_key` (string): API key for Cohere services
- `qdrant_url` (string): URL for Qdrant vector database
- `qdrant_api_key` (string): API key for Qdrant
- `documentation_urls` (list[string]): List of documentation URLs to crawl
- `chunk_size` (int): Size of text chunks in characters
- `chunk_overlap` (int): Overlap between chunks in characters
- `embedding_model` (string): Name of the embedding model to use
- `qdrant_collection_name` (string): Name of the Qdrant collection

## Validation Rules
- Documentation chunk content must not exceed maximum embedding token limits
- Source URLs must be valid and accessible
- Embedding vectors must match the expected dimensionality for the model
- Chunk IDs must be unique within the system
- Metadata must include required fields for proper retrieval

## State Transitions
- Documentation Chunk: NEW → CRAWLED → CLEANED → CHUNKED → EMBEDDED → STORED
- Each state transition requires validation of the previous step's output
- Failed states should include error information for debugging
